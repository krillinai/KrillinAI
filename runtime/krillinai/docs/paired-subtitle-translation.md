# 双语字幕的单行分段与输入保护

YouTube 词级字幕、块级字幕、音频转录和原文 SRT 导入统一通过 `paired_translation.go` 翻译。先按全片/章节建立共享语境与有原文证据的术语表，再按完整父句批量翻译；内容生成与冻结译文排版分别请求。术语审校只返回必要修正。详见[共享语境与术语一致性](subtitle-semantic-context.md)。

## 输入保护

无语义犹豫音默认只从译文省略，不依赖音频入口的 `modal_filter`。初译、表达、长段对齐、审查与恢复共享规则，不额外增加一遍全片 LLM 清洗。规则区分源语言，保留法语/西语 `en`、德语 `um` 等实际词义，以及肯定、否定、不确定性、情绪和引语；英文/中文转录中连续小写 `en` 可作为重复发声处理，单独 `en` 和“嗯”保留歧义，由完整句语境判断。

意群实验路径将 NLP 单独切出的明确犹豫音并入相邻意群，以完整原文切片保留来源 ID 和字节位置。75 显示单位重拆若再次产生纯犹豫音段，只允许该段译文为空，不为填满它而补“呃”或重复邻段译文。两条路径遇到整段纯犹豫音时均本地记录 `omitted_nonsemantic_hesitation`，不交给模型编造译文。导出不产生空字幕，但照常消耗这段原文的时间位置；源文证据保留在检查点，双语字幕中混合内容的原文仍原样保留。全输入只有犹豫音时明确返回没有正文，其他空译文仍判为失败。内容检查点、意群版本及语义请求缓存包含新规则，避免复用旧译文。

预算保护之后增加与VideoLingo相同思路的spaCy句法边界分析：使用实际源语言模型识别句界；逗号右侧具有主语/代词和谓语、两侧有足够上下文时建议切分；随后寻找适合的连接词边界，避免切开相邻数量词。完整父句（超长时为模型预算保护后的语义段）才对应一个sentence_id；NLP结果以该父句的`nlp_segments_hint`保留，不能展平成独立翻译ID。翻译先忽略显示长度和NLP边界，统一处理父句的共享成分、省略与目标语言语序，生成唯一完整译文，再以NLP建议作为字幕边界参考。自然短意群不为填满长度而合并，但可为目标语言语序、固定表达和完整短语移动或合并建议边界。不同于VideoLingo的文本重建，本实现直接截取原文，保留逗号等全部标点。所有结果经过原文完整覆盖、顺序、词/字素及缩写、日期、数字单位和URL保护检查。

NLP后超过20个源语言token的单位会尝试一次语义边界细化，20是独立参考目标，不与50/75显示单位耦合，不强行切成等长段。细化只改变父句的边界建议，不缩小翻译单元。调用失败或结果不合法时保留原NLP建议，仍可在双语显示排版阶段切分。NLP结果及语义边界细化均有检查点，续跑可复用。源语言有模型但没有专用连接词规则时仍可使用句界/逗号分析；无模型语言仍按完整父句翻译，使用通用排版参考。

spaCy通过嵌入的Python worker对全片预处理结果进行一次批量调用，不依赖VideoLingo目录。默认使用`python3`（Windows为`python`），也可用`KRILLINAI_NLP_PYTHON`指定已安装spaCy的解释器；依赖见`requirements-nlp.txt`。按需在该环境预装源语言模型，例如`python -m spacy download en_core_web_md`、`zh_core_web_sm`、`ja_core_news_sm`。优先选择已安装的md/sm/lg模型；翻译任务中不下载模型。解释器、spaCy或对应模型不可用时会明确报告回退，不阻断翻译，也不声称已使用句法模型。参考代码来源和许可见`third_party/VideoLingo-NOTICE.md`。

输入先按 Unicode 句子边界组织语句，结合源语言保护缩写、称谓和部分语言的序数日期。无标点或异常长句在模型调用前按800个 UTF-8 字节预算拆分，优先标点、连接词和 Unicode 词边界。部分仍有生硬边界的长句会额外尝试一次模型语义切分；切分必须保持原文覆盖、顺序、字素及受保护跨度，失败回退确定性结果。模型输入预算与最终字幕显示上限分别控制。

每批前后各两个父句作为上下文，每段最多384字节，仅供理解，不输出到译文；同一批内不再为每句重复发送上下文。批次同时限制句数、请求字节预算和预估响应预算，避免预拆之后再次形成超大请求。请求预算包含 Prompt、JSON、上下文和纠错预留；纠错反馈也限长。响应按当前批次的预估输出加 1024 token 余量设置上限，最少 2048、最多 8192；确认截断后在原有三次输出尝试内翻倍扩大预算。未实现预算接口的翻译器保留原调用方式。预估响应预算为 6500，请求字节预算为 16000。它们是保守估算，不是针对所有模型的精确 tokenizer 或语义扩写上界。异常字素簇或无法满足预算的输入明确报错。

VTT/SRT 文本读取允许单行最多 4 MiB，之后才进入上述模型输入保护，超过读取上限则明确失败。

## 翻译与校验

原文和译文按 `max_sentence_length` 的软目标排版，优先保留完整意群，必要时同步调整配对；同一句内允许译文按目标语言习惯调整语序，原文只能顺序切分，完整覆盖检查仅允许边界空白变化，保留段内空格与其他字符。

存在有效的多段NLP建议时附带 `nlp_segments_hint`；否则超过原文显示目标的输入附带 `source_segments_hint`，由本地按词及字素边界生成。后者仅为机械长度参考，不应照搬生硬边界。末尾两段优先标点及从句边界，避免悬空主语，长度均衡作为次要参考。两类建议均计入请求预算，父句不会因批次大小再次拆成独立翻译任务；内容生成不接收这些提示；之后的排版请求统一给出原译分段，并进行双侧校验。

长度采用字素簇近似显示单位：宽字符或全角字符簇计2，其他基础字素簇计1，组合符、连接符和方向控制符不重复计宽，空格也计入显示宽度。使用 `github.com/clipperhouse/uax29/v2` 的 Unicode 字素、词和句子边界，不按 UTF-8 字节或单个 rune 强行截断。50单位约为25个汉字，包含中文标点；该计数不等同于实际字体的像素宽度。

内容请求只返回ID与完整译文`target_text`，不承担拆句和显示限制。排版请求仅接收完整父句、冻结译文和边界建议，返回`segments`配对数组，不再回显完整译文，每条直接包含`source`和`target`。这种结构避免两个独立数组出现段数不一致，每一对仍检查两侧实际内容，禁止空字符串占位。全部 `target` 拼接必须与完整译文一致，覆盖检查仅允许边界空白变化，保留段内空格与其他字符；出现重复、遗漏、改写或乱序即拒绝，避免对每个原文片段重新翻译整句。内容与排版分别按实际请求和预计响应预算合批，尊重已有批次大小；短单段可本地配对。有效初译立即保存，只重试失败ID。结构校验不能证明完整译文的语义正确，仍需抽查。

本地严格检查 JSON、ID、顺序、两侧片段数量、实际内容、单行、字素边界、原文及译文覆盖和完整句子的目标语言特征。长度和边界质量另作排版评估。禁止实际换行、Unicode 换行控制符和会被 ASS 解释为换行的字面量转义。源文清理保留 ZWJ/ZWNJ，避免破坏 Emoji、印度文字和波斯文等内容。音频语气词过滤仅作用于无实际含义的译文填充词。

`max_sentence_length` 是原译两侧的软排版目标，默认50，对比测试可配置75；75显示单位约为37个纯全角字素。它不再按“目标+10%”拒绝内容。用连续的超长成本和坏边界成本比较现有配对片段的保留与相邻合并；仅允许跨存在结构风险的边界回并，正常意群不因减少条数而合并。NLP建议与译文从句标点共同支持的边界不单凭偏短就自动回并；明确的主谓风险、一两个宽字符等极短尾巴仍保留风险成本，复杂语法交给模型边界审校。短残片、明确的悬空主语比少量超长更值得修复；明显过长仍请求模型在自然意群处重排，不无限合并成长字幕。纠错提供两侧实际显示长度及具体段落，允许继续细分过长的NLP建议，不能把建议误当成不可再分的单位。排版版本为6，旧检查点会重新检查排版；NLP建议变化时复用父句译文，只重置排版审校状态。

合并使用完整原文和完整译文中的精确连续片段，恢复边界的原始空格。不得分别按比例拆分两种语言，不改写译文，不跨sentence_id，不跨明确的独立回答句末。字符宽度与结构规则覆盖Unicode书写系统；短片段评分是结构风险提示，并非完整的多语言语法分析。复杂修饰关系仍依赖模型理解。

边界审校只保留成功句的完成状态，失效修正仅使对应句待审，恢复时不重做其余成功句。单段无需模型审校，完成标记会写回内存及检查点。

分段若只缺少边缘标点，可从完整译文恢复该标点并重新校验；段内文字、顺序或内容不同不能这样修复。多余分段失效而完整原译本身适合显示时，可直接恢复为完整配对并标记排版成功。

本地无法解决的明显长段或危险边界，仅对失败句发出排版纠错，锁定已取得的target_text。完整译文的恢复状态与排版状态分开：检查点额外记录layout_version、layout_target、layout_fallback和layout_reviewed。改变长度目标、旧版排版或排版未完成的续跑，可复用完整译文再排版，不重新翻译。更换本轮主翻译提示词会产生新的内容缓存指纹；不迁移旧指纹缓存。词时间映射由合并后的连续原文重新生成，普通中英双语字幕仍共享编号与时间。

多段句在内容修订后增加一次语义边界审校，提供源语言、目标语言、完整原译和全部配对片段，逐对检查内容对应，不能以全文含义正确代替逐段匹配。每个输入父句必须返回明确的`aligned`、`natural_boundaries`及具体理由；不能把空修正列表当作已完成检查的证据。优先只移动切口，严格校验原译覆盖。若目标语语序导致仅移动切口无法自然对应，可显式返回`rewrite=true`重组该父句；程序从片段构成唯一候选，必须另外独立核验全部原文含义、术语及实际新边界，两项均通过才采用。未声明改写的响应仍不能改变冻结译文。单段句不增加此调用。审校成功状态写入句级检查点；失败保留当前完整原译并标记待审校，续跑仅补审校。同批一条无效修正不影响其他成功句，修订元数据只在本地保留，不重复发送。排版版本更新后复用内容、重做旧版排版与审查。此步骤不能保证所有语法边界都正确，需保留真实字幕抽查。

### 译后75显示单位检查

以上步骤继续使用配置的软目标（例如65），整句翻译、NLP建议、上下文、术语和短残片修复流程不变。边界审校后、交付和导出前，另对每一条配对的原文与译文检查75显示单位上限；缓存恢复也走此检查。未超长的配对不增加模型请求，不因这个步骤改变文字和边界。此处沿用上面的Unicode宽度规则，75不是75个汉字，也不等于实际字体的像素宽度。

仅处理超过75的配对。同一翻译批次有多个超长配对时，每组最多4对合批生成，并用另一个独立请求逐条复核含义与切口；两项均通过才采用。只重试失败项，成功项立即保存；超预算或无法解决的少量配对交给逐条恢复。逐条恢复时，提供完整父句、上下文、术语和父句NLP建议，重新同步划分两侧。最多三次输出尝试，每次仍检查实际长度、覆盖、顺序、非空配对、单行和受保护的词/字素边界；最终阶段不再调用会将合格短段回并成超长段的软长度优化，由独立意群复核判断短段是否合理；不能用机械截断或空白占位满足长度。新增切口由独立的意群与逐段对应检查确认，只返回是否合格及理由，不通过审校再合并或改动字幕。检查只作用于当前超长片段；长度合格但存在生硬边界、逐段内容错配或无法完成审查时，仍继续本轮重试预算。

第一次冻结已有完整译文，只移动分段边界。若目标语言把从句移到前面，无法与源文顺序连续配对，后两次允许在必要时调整当前超长片段的表达；不进行全片重译。局部三次都失败且父句有多对字幕时，回到完整父句，直接允许必要改写，避免重复已失败的冻结尝试；父句恢复仍限三次，且必须重新检查全部含义、术语及每道新边界。局部改写除结构校验外，检查已确认术语，并单独请求语义复核，核对事实、数字、否定、条件、时间和共享成分等。复核拒绝或无法完成时不采用新译文；具体拒绝理由传给下一次输出尝试。模型复核仍需真实字幕抽查，不能视为语义正确的绝对保证。

最终重排只要求返回segments，避免模型同时生成完整译文与片段而产生两份冲突的内容。冻结模式从既有完整译文校验连续覆盖，并恢复可确定的边界标点；允许改写后，程序从所有target片段顺序构成唯一候选全文，再执行全部结构校验和独立语义、边界复核。不能以拼接成功代替语义核验。审校允许完整目的/条件/原因从句独立显示，要求整组字幕连读自然；不能仅因一条以连接词开头而拒绝，短语内部断裂及逐段错配仍拒绝。

重拆另提供程序计宽的原文候选片段，帮助模型识别实际长度；候选是机械参考，不替代NLP或两种语言的意群判断。超长错误反馈要求移动切口或增加意群，不能重复同一超长边界；真实口语中已中断的起句可作为有对应译文的中断意群，不能因此发明新内容。

局部改写的独立核验同时提供替换后父句的完整译文，核对与其余片段合并后的事实、逻辑和重复，不能仅检查局部是否译得正确。程序另拒绝把原来仅出现一次的实质目标片段复制到同一父句的多个字幕中，保留原有的强调重复；失败交回父句恢复。对“当作/视为/看作/称为”后直接断开宾语的明确汉语结构增加本地检查，普通软排版先尝试合并，最终重拆仍拒绝该切口；明确标点或口语中断不按此规则处理。有限规则只覆盖明确结构，不能代替其他语言的句法分析及独立语义审查。

最终边界核验携带仅适用于该父句的术语释义，避免与内容核验对同一词作出冲突解释；术语仍为参考，原文为准。完整后置修饰短语可承接上一条的中心词单独显示，例如“a collection of paintings / from different eras”对应“一批画作，/ 来自不同时代。”，需与“a / large collection”式内部断裂区分。此规则要求短语内部完整、目标语承接自然，并逐对保留角色和信息，不允许借用其他片段的作者或主题来掩盖错配。

超长内容先以待排版状态写入原有句级检查点。有限尝试中取得的候选如果已通过内容和意群核验，且缩短了最长字幕或降低了总超长量，即使仍有少量超长，也保留其中最好的版本。后续片段和必要的父句恢复失败时，保留前面已核验的局部改进，只让尚未修复的部分沿用原片段。没有取得有效改进，或排版接口重试耗尽时，记录提示并沿用原有完整译文和分段继续导出；未通过核验的候选不替换原译，回退状态保留在检查点中。因此，75显示单位是优先修复目标，失败回退时不保证最终字幕满足该长度。任务取消和检查点写盘错误仍向上传播。最终长度检查独立执行，不需要修改既有主翻译提示词或使已有内容缓存失效。

初译内容校验失败后附具体问题和上一轮结果，最多三次输出尝试，前两次使用批量JSON，最后一次改为逐句请求，仍计入同一句的三次预算。429和5xx等临时接口错误使用独立的 `translate_max_attempts` 退避预算，实际次数限制在1至3次，持续限流也不会无限等待；支持取消，不消耗内容纠错次数。单句未能取得有效完整初译时，使用原文保留该句及其时间位置，并在句级检查点写入 `translation_fallback_reason`。默认内容修订未完成、且跨语言正文仍与原文完全相同时，也明确记录为失败后沿用原文；已通过修订的专名、URL和合法共用词允许原样保留。

部分正文翻译成功时，继续导出完整字幕，结果的 `warnings` 提示未翻译条数，`translation_failures` 记录对应句子ID、原文和失败原因；HTTP任务状态及流水线响应均返回这些字段，流水线清单同时持久化。保留原文的句子不会被标记为翻译审校成功。按相同输入与工作目录续跑时，仅重新初译这些失败句，复用其他已取得的译文；修复后清除对应失败记录和旧警告。正常译文需要补做的审校或排版仍按已有检查点继续。

全部正文都无法翻译时仍返回任务失败，检查点保留以供续跑；纯犹豫音的省略不计为正文翻译成功。多段音频按整片汇总，不会因为某一个音频片段恰好只有失败句就提前终止，重复片段也分别计数。任务取消、检查点写盘错误等真实执行错误继续向上传播。有效完整译文立即写入句级检查点；后续修订或核验耗尽时保留修订前原译继续处理，不将被拒候选标为已通过核验。

KrillinAI可通过可选的 `[llm_fallback]` 配置备用模型，`base_url`、`api_key` 和 `model` 全空时保持单主模型行为，启用时必须完整配置。主源请求失败、超时或返回空/截断响应时，以相同提示词和输出预算调用备用源；业务内容校验失败仍由内容纠错流程处理。每个新请求优先主源，任务取消不触发备用请求。主备请求各有独立超时，仍受父任务取消与截止时间约束；一次逻辑请求可包含主备两次调用，不代表整个任务最多调用模型三次。OpenCreator默认只配置主模型。

DeepSeek V4 的 `deepseek-flash`、`deepseek-v4-flash` 和 `deepseek-v4-pro` 使用 `temperature=0.2`，减少结构和分段的随机变化，并发送 `reasoning_effort=none`，避免推理耗尽字幕 JSON 的输出预算；实测其低强度推理也可能耗尽预算。其他模型保留默认采样，不附加这些参数。接口返回 `finish_reason=length` 时明确报 `llm_translation_truncated`，不把被截断的内容当成完整译文或普通空响应。

## 时间与产物

普通原文、译文和双语 SRT 共享条数、编号和时间区间。时间定位使用去空白后的原文 rune 位置，显示单位不参与时间计算。词内切分在已知词时间内插值；仅有 cue 时间则在原 cue 区间内插值。这不是音素级对齐。

普通字幕和短字幕共用位置映射。短字幕保留完整目标片段，再独立拆分源文；YouTube 使用 `short_subtitle_max_chars`，音频使用 `MaxWordOneLine`，同时保留原文单行显示上限。无词时间的块级字幕保留普通双语兼容输出。匹配不到精确词文本时使用已有 cue 时间，避免再次整词搜索把合法词内片段判为失败。音频转录全文与词列表标点不同的兼容情况仍通过既有匹配器生成 cue，再共用 cue 位置映射。

短字幕字符参数是分组目标，短字幕分组仍用 `max_sentence_length` 限制其原文行（独立的短字幕模式）。最后一组只有一个空白分隔词且不超过12显示单位时，允许回并前一组；无空格文字按同样的短尾长度规则处理。回并后仍必须满足单行硬上限和音频词数限制。直接保留原文中对应的连续片段，不给中文、组合字符或长词内部切分额外插入空格；时间由同一位置映射重新取得。此处理不调用模型。

原文和译文 SRT 的每条文本内部保持单行，双语 SRT 的两行分别对应目标语言和源语言。第三方播放器的视口、字体和自动折行由播放器控制，本功能仅负责翻译、配对、时间轴和字幕文件。
