# 双语字幕的单行分段与输入保护

YouTube 词级字幕、块级字幕、音频转录和原文 SRT 导入统一通过 `paired_translation.go` 翻译。正常路径每批调用一次模型，同时完成翻译、拆段和原译配对；不增加常规的第二次模型拆句或审校。

## 输入保护

输入先按 Unicode 句子边界组织语句，保留既有英文缩写例外。无标点或异常长句在模型调用前确定性拆分，优先 Unicode 词边界，没有自然边界的长词、URL才退到完整字素簇边界。单个输入片段最多 1024 个 UTF-8 字节，显示上限较小时进一步减小输入片段。这个预算与最终字幕显示上限分别控制。

相邻前后各两句作为上下文，每句上下文最多 256 字节，仅供理解，不输出到译文。批次同时限制句数、请求字节预算和预估响应预算，避免预拆之后再次形成超大请求。请求预算包含 Prompt、JSON、上下文和纠错预留；纠错反馈也限长。当前响应上限为 8192 token，预估响应预算为 6500，请求字节预算为 16000。它们是保守估算，不是针对所有模型的精确 tokenizer 或语义扩写上界。异常字素簇或无法满足预算的输入明确报错。

VTT/SRT 文本读取允许单行最多 4 MiB，之后才进入上述模型输入保护，超过读取上限则明确失败。

## 翻译与校验

原文和译文每段分别满足 `max_sentence_length`，任意一侧超限都要增加成对字幕条数。两侧都放得下时要求保持一对；同一句内允许译文按目标语言习惯调整语序，原文只能顺序切分，完整覆盖检查忽略空白但保留其他字符。

超过原文显示上限的输入附带 `source_segments_hint`，由本地按词及字素边界生成，参考片段均不超限且完整覆盖原文。末尾两段优先选择较均衡的词边界或标点边界，减少孤立短尾句。模型优先采用该参考，也可以为译文长度和语义对应调整边界；最终原译分段仍由同一次回答给出，并进行双侧校验。参考数据计入请求预算。

长度采用字素簇近似显示单位：宽字符或全角字符簇计2，其他基础字素簇计1，组合符、连接符和方向控制符不重复计宽，空格也计入上限。使用 `github.com/clipperhouse/uax29/v2` 的 Unicode 字素、词和句子边界，不按 UTF-8 字节或单个 rune 强行截断。50单位约为25个汉字，包含中文标点；该计数不等同于实际字体的像素宽度。

同一次模型回答先返回整句完整译文 `target_text`，再返回 `segments` 配对数组，每条直接包含 `source` 和 `target`。这种结构避免两个独立数组出现段数不一致，每一对仍检查两侧实际内容，禁止空字符串占位。全部 `target` 拼接必须与完整译文一致，覆盖检查忽略空白但保留其他字符；出现重复、遗漏、改写或乱序即拒绝，避免对每个原文片段重新翻译整句。此校验不增加正常路径的模型调用次数，也不能保证完整译文本身没有语义重复，仍需抽查。

本地检查 JSON、ID、顺序、两侧片段数量、实际内容、两侧长度、单行、字素边界、原文及译文覆盖和完整句子的目标语言特征。禁止实际换行、Unicode 换行控制符和会被 ASS 解释为换行的字面量转义。源文清理保留 ZWJ/ZWNJ，避免破坏 Emoji、印度文字和波斯文等内容。音频语气词过滤仅作用于无实际含义的译文填充词。

撤销模型多余切分时，必须两侧完整文本都满足长度上限，并能确认译文边界如何连接；无法确定是否为词内切分时保留原配对，避免引入或删除词间空格。

结构校验失败后附具体问题和上一轮结果，整批最多三次输出纠错。429和5xx使用独立的 `translate_max_attempts` 退避预算，支持取消，不消耗结构纠错次数。失败明确报错，不回填源文冒充译文。并发窗口全部成功后才按原顺序提交检查点。

DeepSeek V4 的 `deepseek-flash`、`deepseek-v4-flash` 和 `deepseek-v4-pro` 使用 `temperature=0.2`，减少结构和分段的随机变化，并发送 `reasoning_effort=none`，避免推理耗尽字幕 JSON 的输出预算；实测其低强度推理也可能耗尽预算。其他模型保留默认采样，不附加这些参数。接口返回 `finish_reason=length` 时明确报 `llm_translation_truncated`，不把被截断的内容当成完整译文或普通空响应。

## 时间与产物

普通原文、译文和双语 SRT 共享条数、编号和时间区间。时间定位使用去空白后的原文 rune 位置，显示单位不参与时间计算。词内切分在已知词时间内插值；仅有 cue 时间则在原 cue 区间内插值。这不是音素级对齐。

普通字幕和短字幕共用位置映射。短字幕保留完整目标片段，再独立拆分源文；YouTube 使用 `short_subtitle_max_chars`，音频使用 `MaxWordOneLine`，同时保留原文单行显示上限。无词时间的块级字幕保留普通双语兼容输出。匹配不到精确词文本时使用已有 cue 时间，避免再次整词搜索把合法词内片段判为失败。音频转录全文与词列表标点不同的兼容情况仍通过既有匹配器生成 cue，再共用 cue 位置映射。

短字幕字符参数是分组目标，普通字幕的 `max_sentence_length` 是所有原文行的硬上限。最后一组只有一个空白分隔词且不超过12显示单位时，允许回并前一组；无空格文字按同样的短尾长度规则处理。回并后仍必须满足单行硬上限和音频词数限制。直接保留原文中对应的连续片段，不给中文、组合字符或长词内部切分额外插入空格；时间由同一位置映射重新取得。此处理不调用模型。

原文和译文 SRT 的每条文本内部保持单行，双语 SRT 的两行分别对应目标语言和源语言。第三方播放器的视口、字体和自动折行由播放器控制，本功能仅负责翻译、配对、时间轴和字幕文件。

## 验证

定向测试：

```powershell
go test ./internal/service ./internal/pipeline ./internal/subtitle_style ./pkg/util ./pkg/openai ./internal/cli ./config -count=1 -timeout=120s
```

单元测试覆盖中文、日韩、泰文、阿拉伯文、印地文、重音组合、Emoji和混合文字的字素边界与长度规则，以及两万词无标点输入、双侧长度、不安全切分、重试与取消、词内普通/短字幕时间一致性。

结构检查不等于所有语言的翻译语义均已验证；真实模型的翻译质量仍需抽查。
