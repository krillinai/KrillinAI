# 音频/VTT源文意群分句对比记录

本次两个产品均成功导出完整中文字幕。VideoLingo在本片的中文自然度、阅读负担和token消耗上略占优；KrillinAI的命令占位符处理和部分解释句更好。该结果用于记录当前优化检查点，单一视频不足以推断稳定成功率或普遍质量优势。

## 测试设置

- 视频：https://www.youtube.com/watch?v=bTqizdva04g ，标题为“9 Insane Claude Mods I Already Can't live Without”，时长846秒，英文3,184词。
- KrillinAI：`c822159c`基础上的本次源文意群分句代码。音频/VTT在请求字节预算切分之前运行NLP；细化后的意群成为真实翻译单元，原始SRT入口保留既有父句策略。
- VideoLingo：本地仓库提交`01f843492759be9bbfd1a5cb697b799cc9de1609`。
- 共用YouTube `en-orig`自动字幕和词时间轴，两边分别完整冷跑，没有复用历史译文、术语、NLP或模型分句结果，没有人工术语干预。
- 同模型`deepseek-v4-pro`、temperature 0.2、关闭推理，并发均为3，依次独立运行。
- 两边均按60显示单位控制长度：宽字素通常为2，其他基础字素为1。VideoLingo仅在测试入口替换`calc_len`以统一计数，`target_multiplier=1.0`，流程及Prompt保持原样。
- 耗时从分句到最终双语字幕导出，包含语境/术语、初译、润色/校准、拆分及时间对齐，不包含下载、输入准备、ASR、配音、合成或评阅时间。
- KrillinAI源文310个单元，平均10.27词、最长31词；VideoLingo语义细分后337个单元、最长20词。

## 已发现的问题与反例

- KrillinAI第233—234条重复表达“已经积累的进展”；第360条把“共享屏幕之前”变成重复的“打开这个模组”，遗漏开启时点；第404条把账户中已安装的项目收窄成“在运行”。这些问题不依赖长度超限才能发生。
- KrillinAI第312条英文宽65、中文宽37，排版重试耗尽后保留完整内容。中文本次没有超60，英文侧仍有1条超长。
- KrillinAI第84条时长1秒，译文“然后Claude就会把它构建出来。”为17个非空白字符；VideoLingo同位置为“Claude就能帮你做出来”，13个字符。长度达标仍可能阅读过快。
- VideoLingo保留`{slash} handoff`、`{slash} replay`、`{slash} mods`等源转写占位符，KrillinAI正确转换为`/handoff`、`/replay`、`/mods`，命令可用性更好。
- VideoLingo第269—270条重复“团队”，且部分中文照搬英文后置状语；KrillinAI“短期记忆容量有限”的解释也比该版“只能容纳这么多内容”更直接。
- 两边均将`under 12 words`译成“不超过12/12以内”，未严格保留“少于12”的边界。
- 40项事实检查中，KrillinAI部分项是zip格式被泛化和上述数量边界；VideoLingo部分项是两项命令占位符和上述数量边界。预设事实点未覆盖全文全部问题，通过数不是全文准确率。

## 评阅与输入边界

评分量表及40项事实点在最终字幕生成前固定。全文按250源文词分成13个连续窗口，每窗五维各按0—10、0.5分步长评阅，再按源文词数加权。所有435/437条成品均覆盖。以中性A/B展示并锁定评分后读取映射，但评阅者可从风格及工程指标推断身份；这是单助手文字评阅，不是独立盲评。约1.6分差距应视为本片的小幅差异。

原文内容同序覆盖：KrillinAI去空白后逐字符一致；VideoLingo删除引号格式及136个逗号，核对后没有单词内容遗漏。没有将标点格式变化当作漏译。

自动字幕存在cash/cache clock、roles/rules、产品名和人名误识别歧义，末尾about之后原本就缺少宾语，未要求译者凭空补造。时间轴使用平台词起点，词尾取下一词起点；两个多词片段在原段内插值，最后词尾固定846秒。本次没有音频核听或逐帧播放同步验收，也不验证视频中的产品和价格主张是否真实。

共同输入VTT的SHA-256为`3289f2b7700ced44f28f00b0c05d057da31a16c1100b1aa83d6a5619f68b5834`；词级输入SRT为`d7461c769e2664bf6eb3abea7111bdaede79d5c1362a0478f098c01ee2c69d65`。
