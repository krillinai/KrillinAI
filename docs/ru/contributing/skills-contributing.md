Skill — это папка внутри [`skills/`](../../../skills/) с файлом `SKILL.md` в корне, следующая [соглашению `SKILL.md`](https://agentskills.io). Она упаковывает переиспользуемый рабочий процесс агента: когда его использовать, какие команды или инструменты вызывать и как интерпретировать результаты. Это руководство объясняет, как добавить Skill.

---

## Что Skill ЕСТЬ / чем НЕ является

**Skill ЕСТЬ:**
- Повторяемый рабочий процесс, которому может следовать агент, описанный на естественном языке плюс команды.
- Предметные знания, которым не место в основном коде: как вызвать этап CLI, как структурировать промпт для медиапровайдера, как валидировать план.
- Небольшой объём. Одна папка, один `SKILL.md`, необязательная `references/` для длинных материалов, которые агент читает по требованию.

**Skill НЕ является:**
- Продуктовой функцией. Изменения UI, новые эндпоинты Runtime и новое поведение рабочего пространства — это вклад в код (`apps/web/`, `apps/daemon/`).
- Копией существующего Skill с немного изменённой формулировкой. Если ваше изменение улучшает существующий процесс, отредактируйте тот Skill напрямую.
- Обёрткой вокруг учётных данных или локальных путей конкретного пользователя. Skill должен работать из чистого чекаута.

## Быстрый старт

```bash
git clone https://github.com/krillinai/OpenCreator.git
cd OpenCreator
corepack enable && pnpm install
cp -r skills/krillinai-tts skills/<ваш-skill>   # начните с ближайшего существующего Skill
# отредактируйте skills/<ваш-skill>/SKILL.md
pnpm web:dev                                    # проверьте, что агент распознаёт его в диалоге
```

Самый быстрый путь — скопировать Skill, наиболее близкий к вашей идее, и переписать его: существующие Skill `krillinai-*` показывают ожидаемую структуру и тон.

## Анатомия Skill

```
skills/<ваш-skill>/
├── SKILL.md            # обязательно: frontmatter + инструкции
└── references/         # необязательно: длинные документы, на которые ссылается SKILL.md
    └── cli-contract.md
```

`SKILL.md` начинается с YAML frontmatter:

```yaml
---
name: ваш-skill
description: Use when <условие срабатывания>, including <основные возможности>.
---
```

Два правила, которые применяют ревьюеры:

- **`name` должен совпадать с именем папки.** Строчные буквы, через дефис.
- **`description` — это поверхность обнаружения.** Именно её агент читает, чтобы решить, применим ли этот Skill. Пишите в формате "Use when …", называйте триггер и результат, уложитесь в одно-два предложения. Расплывчатые описания («помогает с видео») возвращаются на доработку.

Тело должно охватывать, по порядку:

1. **Когда использовать** — один абзац.
2. **Команды** — блоки кода с точным вызовом, включая необходимые переменные окружения или рабочие каталоги.
3. **Входы и флаги** — таблица для всего неочевидного; отметьте обязательное и необязательное.
4. **Выходы** — куда попадают результаты и как их читать (например, «читайте пути из манифеста»).
5. **Режимы отказа** — известные ошибки и что с ними делать.

Держите `SKILL.md` удобным для беглого просмотра. Длинные контракты, полные списки флагов или справочные материалы выносите в `references/` и ссылайтесь относительными путями — агент читает references только при необходимости.

## Локальная проверка

После `pnpm web:dev` начните диалог и опишите задачу, которая должна активировать ваш Skill. Проверьте:

- Агент выбирает Skill для правильных запросов — и не выбирает для несвязанных.
- Команды Skill выполняются из чистого чекаута без ручных правок.
- Пути вывода и обработка ошибок соответствуют документации.

## Критерии слияния

Ревьюер проверит каждый пункт — вставьте список в PR и отметьте:

- [ ] Имя папки и frontmatter `name` совпадают; строчные буквы через дефис.
- [ ] `description` называет условие срабатывания и результат ("Use when …").
- [ ] Команды работают из чистого чекаута; без абсолютных локальных путей и учётных данных.
- [ ] Входы, выходы и режимы отказа задокументированы.
- [ ] Длинные справочные материалы находятся в `references/`, а не в основном тексте.
- [ ] Проверено в реальном диалоге: Skill срабатывает, когда должен, и только тогда.
- [ ] Если Skill пересекается с существующим, PR объясняет, почему нужен отдельный.

## Частые причины отклонения

- **Дубликат существующего Skill** с косметическими правками формулировок — вместо этого улучшите существующий.
- **Замаскированная функция** — Skill работает только вместе с изменениями кода Runtime или UI; отправьте изменение кода отдельным PR.
- **Непроверенные команды** — несуществующие флаги или выходы, не совпадающие с задокументированными путями.
- **Незадокументированные предпосылки** — Skill молча предполагает конфигурацию провайдера, бинарный файл или сетевой сервис.
