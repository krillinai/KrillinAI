# المساهمة بـ Skill (العربية)

الـ Skill هو مجلد داخل [`skills/`](../../../skills/) يحتوي على ملف `SKILL.md` في جذره، ويتبع [اتفاقية `SKILL.md`](https://agentskills.io). يغلّف سير عمل قابلًا لإعادة الاستخدام للوكيل: متى يُستخدم، وما الأوامر أو الأدوات التي يجب استدعاؤها، وكيفية تفسير المخرجات. يشرح هذا الدليل كيفية إضافة واحد.

---

## ما هو الـ Skill وما ليس كذلك

**الـ Skill هو:**
- سير عمل قابل للتكرار يمكن للوكيل اتباعه، موصوف بلغة طبيعية مع أوامر.
- معرفة متخصصة لا مكان لها في الكود الأساسي: كيفية استدعاء مرحلة CLI، وكيفية بناء موجه لمزود وسائط، وكيفية التحقق من خطة.
- صغير. مجلد واحد، ملف `SKILL.md` واحد، ومجلد `references/` اختياري للمواد الطويلة التي يقرأها الوكيل عند الحاجة.

**الـ Skill ليس:**
- ميزة منتج. تغييرات الواجهة ونقاط نهاية Runtime الجديدة وسلوكيات مساحة العمل الجديدة هي مساهمات كود (`apps/web/`، `apps/daemon/`).
- نسخة من Skill موجود مع تعديلات طفيفة في الصياغة. إذا كان تغييرك يحسّن سير عمل موجودًا، فحرّر ذلك الـ Skill مباشرة.
- غلافًا حول بيانات اعتماد أو مسارات محلية خاصة بمستخدم معين. يجب أن تعمل الـ Skills من نسخة نظيفة من المستودع.

## البدء السريع

```bash
git clone https://github.com/krillinai/OpenCreator.git
cd OpenCreator
corepack enable && pnpm install
cp -r skills/krillinai-tts skills/<skill-الخاص-بك>   # ابدأ من أقرب Skill موجود
# حرّر skills/<skill-الخاص-بك>/SKILL.md
pnpm web:dev                                         # تحقق من أن الوكيل يتعرف عليه في محادثة
```

أسرع طريق هو نسخ الـ Skill الأقرب لفكرتك ثم إعادة كتابته — الـ Skills الموجودة `krillinai-*` توضح البنية والأسلوب المتوقعين.

## بنية الـ Skill

```
skills/<skill-الخاص-بك>/
├── SKILL.md            # مطلوب: frontmatter + تعليمات
└── references/         # اختياري: مستندات طويلة يشير إليها SKILL.md
    └── cli-contract.md
```

يبدأ `SKILL.md` بـ YAML frontmatter:

```yaml
---
name: your-skill
description: Use when <شرط التفعيل>, including <القدرات الرئيسية>.
---
```

قاعدتان يطبقهما المراجعون:

- **يجب أن يتطابق `name` مع اسم المجلد.** أحرف صغيرة مفصولة بشرطات.
- **`description` هو سطح الاكتشاف.** إنه ما يقرأه الوكيل ليقرر ما إذا كان هذا الـ Skill ينطبق. اكتبه بصيغة "Use when …"، واذكر المُفعِّل والنتيجة، واجعله في جملة أو جملتين. الأوصاف الغامضة ("يساعد في الفيديو") تُرجَع.

يجب أن يغطي المتن، بالترتيب:

1. **متى تستخدمه** — فقرة واحدة.
2. **الأوامر** — كتل كود بالاستدعاء الدقيق، بما في ذلك متغيرات البيئة أو مجلدات العمل المطلوبة.
3. **المدخلات والأعلام** — جدول لكل ما هو غير بديهي؛ ميّز المطلوب عن الاختياري.
4. **المخرجات** — أين تُحفظ النتائج وكيف تقرؤها (مثلاً، "اقرأ المسارات من الـ manifest").
5. **أنماط الفشل** — الأخطاء المعروفة وما يجب فعله حيالها.

حافظ على `SKILL.md` سهل المسح. انقل العقود الطويلة أو قوائم الأعلام الكاملة أو المواد الخلفية إلى `references/` واربطها بمسارات نسبية — الوكيل يقرأ المراجع فقط عند الحاجة.

## الاختبار المحلي

بعد `pnpm web:dev`، ابدأ محادثة وصف مهمة يجب أن تُفعِّل الـ Skill الخاص بك. تحقق من:

- الوكيل يختار الـ Skill للطلبات الصحيحة — ولا يختاره للطلبات غير المرتبطة.
- الأوامر في الـ Skill تعمل من نسخة نظيفة دون إصلاحات يدوية.
- مسارات المخرجات ومعالجة الأخطاء تطابق الموثَّق.

## معايير الدمج

سيتحقق المراجع من كل عنصر أدناه — الصقها في طلب الدمج وعلّم عليها:

- [ ] اسم المجلد و`name` في frontmatter متطابقان؛ أحرف صغيرة بشرطات.
- [ ] `description` يذكر شرط التفعيل والنتيجة ("Use when …").
- [ ] الأوامر تعمل من نسخة نظيفة؛ بدون مسارات محلية مطلقة أو بيانات اعتماد.
- [ ] المدخلات والمخرجات وأنماط الفشل موثّقة.
- [ ] المواد المرجعية الطويلة في `references/` وليست مضمّنة.
- [ ] تم التحقق في محادثة حقيقية: يُفعَّل الـ Skill عندما يجب — وفقط عندئذ.
- [ ] إذا كان الـ Skill يتداخل مع واحد موجود، يشرح طلب الدمج لماذا يُبرَّر skill منفصل.

## أنماط الرفض الشائعة

- **تكرار لـ Skill موجود** مع تغييرات شكلية في الصياغة فقط — حسّن الموجود بدلًا من ذلك.
- **ميزة متنكرة** — الـ Skill يعمل فقط إذا اقترن بتغييرات كود في Runtime أو الواجهة؛ أرسل تغيير الكود كطلب دمج مستقل.
- **أوامر غير مختبَرة** — أعلام غير موجودة، أو مخرجات لا تطابق المسارات الموثّقة.
- **متطلبات مسبقة غير موثّقة** — الـ Skill يفترض ضمنيًا إعداد مزود أو ملفًا ثنائيًا أو خدمة شبكة.
