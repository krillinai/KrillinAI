# Creator Runtime 连接恢复

## 问题与边界

- 旧面板把没有 Creator Context 显示为 Runtime 未连接。缺少项目上下文与服务断线是两类问题；截图中具体触发上下文丢失的原因并未实锤。
- 首次 Creator 快照请求失败时，以前不会进入 SSE 重连；错误被调用方吞掉，会话一直停在未订阅状态。
- Runtime 健康检查与 Codex 状态读取以前共用失败分支，Codex 暂时不可用会误报整个服务断开。
- Desktop 以前仅自动重启一次，并在 Runtime 恢复时重新加载整个工作区。正式工作区没有接通已有的宿主重启能力。

## 现在的恢复流程

1. Web 与 Desktop 共用 `useRuntimeConnection`，定期检查健康状态。断线按 0.5、1、2、5 秒退避，延迟上限为 5 秒；健康连接每 15 秒检查一次。
2. 健康请求和 Codex 状态请求分别限制为 4 秒。健康成功但 Codex 状态失败时，保留 Runtime 已连接状态，并单独显示 Codex 告警。此超时不用于生成、下载、Whisper 准备或其他长任务。
3. 初次 Creator 快照和后续订阅断开共用恢复逻辑。快照读取限制为 15 秒；临时网络错误自动恢复，认证、项目不存在等不可自动恢复的 4xx 错误停止重试，等待用户操作。
4. 连接恢复只读取权威快照和 Agent 时间线、重新订阅事件。不得自动提交 `run-stage`、Agent turn 或其他可能产生重复费用的业务操作。
5. 暂时没有宿主连接配置时保留已有 Service 和项目数据，避免卸载 Workspace。Creator Context 放在独立模块中，并在开发热更新时保留身份。
6. Desktop 异常退出最多自动重启 3 次，分别等待 0.5、1.5、3 秒；稳定运行 5 分钟或成功手动重启后重置预算。退出应用时取消尚未执行的恢复。
7. 已进入工作区的 Desktop 恢复只通知连接变更，不整页刷新，保留表单和 Composer 草稿。被进程退出中断的任务仍需用户主动继续或重试。

## 用户入口

- 通用 Creator 协作面板显示连接中、自动重连、项目恢复失败及重试次数，并提供“重新连接”。
- 支持宿主重启能力的 Desktop 在连接提示和“设置 → 诊断”提供“重启本地服务”；浏览器不展示无效重启按钮。
- 重启前明确提醒可能中断运行中的任务，不会自动重新提交任务。
- Context 缺失时提示“项目会话尚未初始化”，不再声称 Runtime 已断开。

## 验证方式

- Web 定向测试覆盖初始失败、断线恢复、终止错误、超时和取消、两种 Host 下的业务草稿与 Composer 草稿保留及不重发任务。
- Desktop 单元测试覆盖有限恢复预算、启动失败重试、手动重启重置预算和退出时取消恢复。
- 实际打包 App E2E 反复终止隔离 Daemon，验证自动恢复、预算耗尽后的真实手动重启、草稿保留、Renderer 未重新加载以及不重复执行 Codex Probe。
- `desktop:package` 重建 Web，并校验 App 内 Web 文件列表和哈希与本次 `apps/web/dist` 一致。此验证不意味着其他平台的安装包已验收，也不替换用户已安装的 App。
