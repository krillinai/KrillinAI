# 视频翻译容错与恢复

更新日期：2026-10-19。

本次优化统一作用于 Runtime 中的平台字幕、本地 SRT 导入及音频转录翻译路径。目标是在保留完整译文和原文覆盖的前提下，避免字幕排版或模型输出格式问题中断整项任务。Web 与 Desktop 继续使用同一套 Runtime 实现。

## 长度与排版

- `max_sentence_length` 表示单行显示目标，仍采用 Unicode 字素宽度计数：宽字符计 2，其余基础字素通常计 1。
- 默认容差为目标的 10%，向上取整，至少允许 2 个显示单位。目标 50 时，51–55 直接接受，不追加模型请求。
- 超出容差或存在不自然的分段边界时，先尝试在本地合并已有的相邻对应片段，保留原始边界空白。
- 已取得有效完整译文时，最多追加一次分段纠错，并冻结 `target_text`。模型不得为了排版重新翻译、删减或改写这份内容。
- 纠错仍不满足目标时，保留内容完整且字素安全的已有配对；配对存在遗漏、重复或不安全切分时，恢复为整句原译配对。
- 最终字幕检查继续拒绝空内容和非法换行，长度超出不再单独导致任务失败。极端情况下会保留较长字幕，并报告恢复说明。

## 失败句恢复

每批输出按句子 ID 独立检查。正确句立即保存，下一轮只提交失败句。重复或缺失的 ID 不会被猜测匹配，空白、纯标点和普通整句未译不会被作为完成结果。

尚未取得有效译文时，最多进行三次结构化请求，然后切换为单句完整翻译，移除分段、配对和计数要求。批量输出反复截断时提前切换单句请求。

仍无有效译文的句子延后处理，让其他批次先完成。随后每轮等待 30 秒再逐句恢复，持续保留已完成内容。取消会中断请求及等待，不会继续启动后续请求。

接口重试与内容纠错分别计数。临时超时、网络错误及 5xx 按配置退避重试，底层持续不可用时返回真实错误；429 超过短期重试次数后进入低频等待，并将后续批次降低为串行。已有有效完整译文时，分段优化请求发生故障也可以直接使用已保存内容完成。

恢复过程通过标准 `phase`、`message` 等进度字段传递给现有共享协作面板，未新增模板专属消息框架。

## 句级检查点

检查点存放于任务工作目录的 `translation-checkpoints/<内容指纹>/<句子ID>.json`。

指纹包含输入文本、源语言、目标语言、模型、接口、提示词及语气词过滤配置。显示长度和批次大小不进入指纹；使用同一工作目录恢复时，可以复用已保存译文，避免因为排版参数变化重新翻译。

每句单独通过临时文件、同步及原子替换保存，避免长视频每完成一句都重写整个检查点。有效整句译文在分段纠错之前就会落盘，同一并发窗口中的成功句也不依赖其他句成功才能保存。单句检查点损坏只会使该句重新翻译，读取后的内容仍需通过有效性检查。

恢复要求继续使用原任务工作目录；本次未增加进程退出后自动重新启动任务的后台调度器。

## 时间轴与后续阶段

- 平台词级时间无法匹配完整原文时，回退到原 cue 时间区间。
- 字幕细分导致时间不足时，合并回完整句；短字幕无法在保留字素簇或有效时间的前提下拆分时，保留原字幕块。
- 原始字幕没有有效时间区间、持久化不可写及底层服务不可用等实际阻塞仍会明确报告。
- 已有字幕与后续配音、渲染阶段继续分开保存。本次未修改配音或视频渲染实现，也未以字幕完成替代视频完成。

- 导出 157 条原文、译文和双语字幕；11 条英文原文为 51–55 显示单位，全部正常保留。英文最大 55，中文最大 50，没有超出 55 的字幕。
- 第 24 句分段纠错后仍未达到意群排版要求，保留完整有效译文继续处理，任务成功结束。该句仍存在不自然的分段边界，属于可继续改善的排版质量问题。
- 审计确认全片原文覆盖完整、检查点完整译文全部导出、双语配对与时间一致、无空字幕及非法换行、无时间重叠；首尾时间范围保持 0–272.6 秒。
