# 视频翻译：撤回流程替换，基于上一版修复

日期：2026-10-22。用户要求：若基于上一版修复更容易，就放弃本次流程修改。结论：以 `8b4bd9db4ecb87b20ba5dbf14b71dce7612c085e` 的默认 legacy 链路作为基础更可控，撤回音频/VTT 专用的新策略，保留独立缺陷修复。先确保翻译成功，再提升质量的优先级保持不变。

## 1. 为什么选择旧版作为基础

旧版在相同来源、相同模型的视频对照中一次完成字幕导出，475 条中文字幕最长 72 显示单位；新版 387 条中最长达到 218，且出现新的修饰关系错译和术语不一致。重新核对历史原始请求后确认：OpenCreator 新、旧版目标均为 75，VideoLingo 为 50，此前旧版目标为 50 的记录有误。旧、新版的长度退步不能由目标差异解释；VideoLingo 仍需按不同显示目标的历史成品参考解读。现有证据足以否决本次替换策略，不能据一次运行推断所有素材的质量或成功率。

旧版已有初译保存、可选内容修订、有效同批项保留、有限排版修复和检查点续跑。这些能力无需由新链路重建。继续修补新链路还需补回分段、表达修订、局部排版接纳及完成状态等能力，修改范围反而更大。

## 2. 旧版仍有什么问题

| 问题 | 证据与当前处理 |
| --- | --- |
| VTT 全片词文本去重误删后面真实出现的相同词 | 本片复现丢失 `notion`、`one`；保留基于相邻 cue 和时间证据的修复 |
| 模型返回 `text` 而非 `target_text` 时丢弃已有正文 | 旧对照有 40 条句级实例；保留无歧义别名兼容及冲突检查 |
| 排版审校载荷超预算时整批被跳过 | 原真实首批审校需要 19,893 字节，上限 16,000；新增按实际完整载荷递归拆批，单项仍超限则保持待审，不阻断已保存译文 |
| 工作台重试使用新目录，无法复用 CLI 检查点 | 保留 Daemon 恢复目录接通、ASR 缓存和失败项持久提示；音频/VTT 的降级语境计划固定，避免恢复时因可选语境变化重译全文 |
| 鉴权或额度错误被当作内容问题反复处理 | 保留永久服务错误识别，并用于旧版参考准备与正文阶段；已有成功正文仍保存在检查点 |
| 800 字节预算先于 NLP，可能切坏来源语义；前置模型细化及排版修复调用多 | 已确认的旧版限制，当前没有再次替换分段算法或关闭旧内容修订；需要后续独立的小范围对照，不能宣称全部修好 |

旧版受控运行约 23 分 22 秒、669,998 token，首次正文开始前等待约 7 分 31 秒。回到旧版不会自动消除成本和等待问题；当前先恢复更有依据的质量基线。

## 3. 本次撤回与保留范围

- 撤回 `forMediaTranslation` / `successFirst` 分支，音频/VTT 恢复生产默认 legacy 的分段、修订和排版链路；实验 segmented 开关保持原样，原始 SRT 翻译策略不作额外改造。
- 删除新媒体专用流程和对应策略测试；保留并整理 VTT、译文字段、服务错误及转录缓存的独立回归。
- 撤回“排版尝试后即视为完成”和内容次数持久耗尽的新策略；旧版允许在保留正文的基础上继续处理失败的排版。
- 保留工作台断点目录、未译与排版待调整的结果提示；排版警告对旧版也生效，并在修复成功后清除。
- NLP/Desktop 打包相关的原有工作区修改保持不变。撤回前的完整差异和未跟踪文件已备份到本机临时目录，未使用仓库整体重置。
- 原方案、复审、实施文档标为历史记录，避免后续继续按已撤回策略开发。
